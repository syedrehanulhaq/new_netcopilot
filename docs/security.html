Security Guardrails

Eight independent layers of defence — from the internet edge to device credentials.

Defence-in-Depth Overview

Every request passes through eight security layers in order. A failure at any layer blocks the request — it never reaches the next layer.

Layer 1
Transport Security
🔒
TLS / HTTPS
All traffic encrypted in transit via nginx + Let's Encrypt
TLS 1.2+ enforced
🛡️
HTTP Security Headers
Applied to every response by middleware
X-Frame-Options: DENY · nosniff · XSS-Protection · HSTS · Referrer-Policy
🚫
Clickjacking Prevention
X-Frame-Options: DENY blocks the UI from being embedded in iframes
Layer 2
Rate Limiting
⏱️
Per-Client Rate Limit
Applies to web chat, Slack, Teams, and alert ingest
60 requests / 60 seconds per IP / user
📊
Memory-Bounded Tracker
Rate limit state is capped to prevent memory exhaustion under load
Max 10,000 tracked clients
🔄
Auto Eviction
Stale entries are evicted automatically — no memory leak
HTTP 429 returned on breach
Layer 3
Authentication
🔑
SSO via Auth0
Users authenticate with corporate Google / Azure / Okta — no local passwords
OAuth 2.0 + OIDC
🎫
Signed Session Tokens
Sessions are cryptographically signed using SESSION_SECRET — tampering is detectable
itsdangerous · HMAC-SHA256
🤖
API Keys (Automation)
Pipelines authenticate with static API keys — each key is bound to a specific role
key:role format in settings
📨
Slack HMAC Verification
Every Slack request has its signature verified against SLACK_SIGNING_SECRET before processing
v0= HMAC-SHA256 · replay-safe
Layer 4
Authorisation (RBAC)
👤
Role: noc
Read-only diagnostics — interface health, routing, ping, traceroute
Cannot create tickets · Cannot change settings
🎫
Role: noc-ticket
All diagnostic tools plus Jira ticket create / update / comment
Cannot change settings
⚙️
Role: admin
Full access including settings, inventory, playbooks, and all integrations
Restricted to named accounts
🔧
LLM Tool Filtering
The LLM only sees tools permitted for the user's role — filtered at dispatch time
Role checked on every request
Layer 5
Input Validation
🔍
Device Name Regex
Device names validated before any SSH connection is opened
^[a-zA-Z0-9._-]{1,64}$ — injection impossible
🌐
Host / IP Regex
Hostname and IP fields validated during CSV device import
^[a-zA-Z0-9._:-]{1,255}$
📋
YAML Injection Guard
CSV imports are field-validated before writing to devices.yaml — prevents YAML injection
Layer 6
Device Protection
⚡
Circuit Breaker
Faulty devices are automatically isolated after 3 consecutive failures
3 failures → OPEN for 60s → HALF-OPEN probe
🕐
Executor Timeout
All SSH and NETCONF calls are bounded — a hung device cannot block the server
60s per device call · asyncio.wait_for
📦
Pool Size Cap
Device connection pool is capped to prevent memory exhaustion
Max 1,000 tracked devices
👁️
Read-Only Commands
Only show / display commands are issued — no config push, no commit, no destructive ops
By design — no write tools exist
Layer 7
Credential Security
🗄️
Settings Database (Priority 1)
UI-updated credentials stored in SQLite settings.db — overrides .env so UI changes take effect immediately without restart
settings.db → env vars
📄
Environment Variables (Fallback)
.env file used at initial setup or Docker deployments — git-ignored, never committed to version control
🚿
Error Scrubbing
Credentials are stripped from all error messages and logs before they leave the adapter
_scrub_error() in all adapters
🙈
Log Redaction
Configurable field redaction in logs — password, token, api_key, secret redacted by default
Extends via LOG_REDACTION_FIELDS
Layer 8
Audit Trail
📝
Tool Call Logging
Every device tool call is logged with timestamp, user, device, tool name, and duration
🎫
Jira Ticket Tagging
All AI-raised tickets are tagged so teams can distinguish human vs AI-created tickets
🏥
Health Endpoint
/health reports Vault status, adapter connectivity, and degraded modes — for monitoring
vault_degraded flag · per-adapter status

Role-Based Access Control

Roles are assigned at login via Auth0 group claims or per API key. The LLM receives only the tools its role permits — a noc user cannot trigger ticket creation even by asking.

Role Who uses it Device Tools Jira Tickets Prometheus / Syslog Settings / Admin
noc NOC engineers (read-only shift) ✓ All 55 tools ✗ Blocked ✓ Query only ✗ Blocked
noc-ticket NOC engineers (full shift) ✓ All 55 tools ✓ Create / Update / Comment ✓ Query only ✗ Blocked
admin NetOps leads / platform team ✓ All 55 tools ✓ Full Jira access ✓ Full access ✓ Full access
api-key Automation / monitoring pipelines Role assigned per key — any role above, set in settings

Circuit Breaker — Device Protection

Prevents a sick or unreachable device from blocking the server or amplifying an outage. Each device has independent state.

⬤ CLOSED — Normal
Device is reachable. All calls go through. Success resets failure counter.
Transitions to OPEN after 3 consecutive failures
⬤ OPEN — Isolated
Device is blocked. All calls return an error immediately without attempting SSH. Server is protected.
Held for 60 seconds · then transitions to HALF-OPEN
⬤ HALF-OPEN — Probing
One test call is allowed through. If it succeeds, circuit closes. If it fails, circuit re-opens for another 60s.
Success → CLOSED · Failure → OPEN again

Credential Storage

NetCopilot checks two sources in order. Settings DB wins over the .env file so credentials updated via the UI take effect immediately without a restart.

1
Settings Database (settings.db)
Credentials saved via the NetCopilot Settings UI — stored in a local SQLite database, never committed to git, takes effect immediately without restart
HIGHEST PRIORITY
↓ only if not set in settings.db
2
Environment Variables / .env file
Set at deployment time — .env is git-ignored and never committed to version control. Useful for initial setup or Docker deployments via environment injection.
FALLBACK
Credential Leak Prevention
All device adapters run _scrub_error() before returning any error — credentials are stripped from exception messages before they reach logs or API responses. Log redaction additionally masks password, token, api_key, secret, and authorization fields in all structured log output.

What the LLM Cannot Do

The most common question in demos. These are architectural constraints — not just guidelines.

🚫
Cannot modify device config
No write tools exist. The LLM tool set contains only show / display commands. There is no configure_terminal, no commit, no destructive command.
🚫
Cannot invent device data
The LLM can only respond with what the device actually returned. It cannot fabricate interface states, BGP routes, or error counts — the tool call returns real CLI output.
🚫
Cannot exceed its role
A noc user asking "create a ticket" receives a filtered tool list with no Jira tools. The LLM cannot call a tool it was never given.
🚫
Cannot access unenrolled devices
Only devices listed in devices.yaml or the inventory integration are reachable. The LLM cannot SSH to an arbitrary IP.
🚫
Cannot bypass rate limits
Rate limiting applies at the HTTP layer before the LLM is invoked. A runaway automation loop is blocked at 60 requests/minute.
🚫
Cannot run unbounded tool loops
The agentic loop is hard-capped at 10 tool turns per conversation turn. The LLM cannot run indefinitely.
