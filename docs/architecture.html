Circuit Breaker — Per-Device Resilience

Every device call goes through adapters/devices/pool.py. If a device fails 3 times in a row, its circuit opens for 60 seconds — all further calls are rejected immediately without blocking a thread. The circuit moves to HALF_OPEN after the timeout and allows one probe call to test recovery.

● CLOSED — normal operation ● OPEN — failing fast, 60s timeout ● HALF_OPEN — one probe allowed

How the LLM Selects Tools

Single tool — direct query

User asks about one specific thing. LLM picks the most relevant tool based on the vendor-prefixed tool name and the device's registered vendor in devices.yaml.

-- Query --
"show ge-0/0/0 status on srx"

-- LLM reasoning --
srx → vendor=junos (from devices.yaml)
"status" + single interface
→ junos_get_interface_health(
    device="srx",
    interface="ge-0/0/0"
  )

Multiple tools — playbook match

User reports a known scenario. System prompt includes the playbook list. LLM calls run_playbook, which executes all steps in sequence.

-- Query --
"ge-0/0/0 is down on srx"

-- Playbook: link_down --
steps: [get_interface_health,
        get_link_health]

-- Runner calls both --
junos_get_interface_health(srx, ge-0/0/0)
junos_get_link_health(srx, ge-0/0/0)

Playbooks — NOC Runbooks as YAML

Playbooks map known network problem patterns to tool sequences. Adding a new playbook requires zero code changes — just add a YAML entry to playbooks/playbooks.yaml and reload.

link_down

Interface down/down investigation

get_interface_health get_link_health

🚨 Critical if oper_status=down + admin_status=up

link_flap

Interface flapping detection

get_top_flapping_links get_interface_health get_interface_counters

⚠️ Warning if carrier_transitions > 3

bgp_down

BGP neighbor down investigation

get_bgp_summary get_bgp_neighbor_status get_ping

🚨 Critical if state=Idle or state=Active

crc_errors

High errors / CRC investigation

get_interface_health get_interface_counters get_optics

⚠️ Warning if crc_errors > 0

isis_down

IS-IS adjacency down investigation

get_isis_health get_isis_neighbors get_mtu_info

🚨 Critical if state=Down or state=Init

cpu_high

High CPU / memory investigation

get_cpu_memory

⚠️ Warning if cpu_percent or memory_percent > 80

Before vs After — What Changed

Aspect v1 — Monolith v2 — Adapter Architecture
Tool dispatch Hardcoded if-elif blocks in app.py ToolDispatcher routes by vendor prefix to in-process adapters
Adding a vendor Edit core app.py + tools/*.py Add adapters/devices/newvendor.py — zero changes to app.py
Device connections New SSH connection per tool call Connection pool with 60s TTL + per-device circuit breaker
LLM provider OpenAI only, hardcoded OpenAI / Claude / Local LLM — switchable from Settings UI
Credentials Environment variables only (restart required) Settings UI → SQLite, read at connect time. Vault for prod.
Device inventory LLM had to guess or ask the user devices.yaml injected into every prompt, vendor auto-detected
Authentication API keys only Auth0 SSO + role-based tool access (admin / noc / noc-ticket)
Conversation memory Stateless — no history between requests Tool results saved to memory.db, available in follow-up turns
Playbooks Not supported YAML runbooks — editable from admin UI, zero code changes
Observability Basic logging Structured JSON audit logs, /metrics endpoint, /health/llm
