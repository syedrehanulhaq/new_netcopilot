How the LLM Selects Tools

Single tool — direct query

User asks about one specific thing. No playbook match. LLM picks the single most relevant tool.

-- Query --
"show ge-0/0/0 status on srx"

-- LLM reasoning --
srx → Juniper (from inventory)
"status" + single interface
→ get_interface_health(
    device="srx",
    interface="ge-0/0/0"
  )

Multiple tools — playbook match

User reports a known scenario. LLM matches to a playbook and runs all steps in sequence.

-- Query --
"ge-0/0/0 is down on srx"

-- Playbook: link_down --
steps: [get_interface_health,
        get_link_health]

-- LLM calls both --
get_interface_health(srx, ge-0/0/0)
get_link_health(srx, ge-0/0/0)

Playbooks — NOC Runbooks as YAML

Playbooks map known network problem patterns to tool sequences. Adding a new playbook requires zero code changes — just add a YAML entry.

link_down

Interface down/down investigation

get_interface_health get_link_health

🚨 Critical if oper_status=down + admin_status=up

link_flap

Interface flapping detection

get_top_flapping_links get_interface_health get_interface_counters

⚠️ Warning if carrier_transitions > 3

bgp_down

BGP neighbor down investigation

get_bgp_summary get_bgp_neighbor_status get_ping

🚨 Critical if state=Idle or state=Active

crc_errors

High errors / CRC investigation

get_interface_health get_interface_counters get_optics

⚠️ Warning if crc_errors > 0

isis_down

IS-IS adjacency down investigation

get_isis_health get_isis_neighbors get_mtu_info

🚨 Critical if state=Down or state=Init

cpu_high

High CPU / memory investigation

get_cpu_memory

⚠️ Warning if cpu_percent or memory_percent > 80

Before vs After — What Changed

Aspect v1 — Monolith v2 — MCP Architecture
Tool location Hardcoded in app.py (if-elif blocks) Separate MCP servers, discovered at startup
Adding a vendor Edit core app.py + tools/*.py files Deploy a new MCP server — zero changes to app.py
LLM provider OpenAI only, hardcoded OpenAI / Claude / Local LLM — switchable from UI
Credentials Environment variables only (restart required) Settings UI → saved to SQLite, read at connect time
Device inventory LLM had to guess or ask the user Injected from devices.yaml into every prompt
Authentication API keys only Auth0 login + role-based tool access
CLI parsing Regex parsers on raw SSH output (fragile) NETCONF → structured XML → PyEZ (reliable)
Playbooks Not supported YAML runbooks — editable from admin UI
Observability Basic logging Structured JSON audit logs + /metrics endpoint
