📡 Browser sends — HTTP POST /chat
POST http://localhost:8001/chat Content-Type: application/json X-API-Key: abc123:noc-ticket { "message": "Why is BGP down on pe1?", "user": "syed" }
What is JSON? JavaScript Object Notation — a text format computers use to pass structured data. The browser packages your message and username into this JSON object and sends it as an HTTP POST (like mailing a letter). The X-API-Key header is your credential — the server checks this to know who you are.

Why use a playbook instead of letting the LLM decide what to check? Playbooks are deterministic — the same steps every time, measured, logged, with scoring rules. The LLM might forget to check ping, or check things in a different order. A playbook never forgets, always runs in the same order, and returns a structured severity assessment (Critical/Warning/Info) the LLM can reason about.

Why run_in_executor? NETCONF/SSH is blocking — the Python code stops and waits (sometimes 2-5 seconds) for the router to reply. FastAPI runs on an async event loop that can't freeze. run_in_executor moves blocking code into a separate OS thread so the event loop stays free to handle other requests. Connection pool (pool.py): SSH connections are cached for 60s — so the second call to the same router reuses the open session instead of reconnecting.

Why must tool results go back as role:"tool" messages? The OpenAI API requires it — the conversation protocol is: user asks → assistant calls tool → tool result added → assistant reads result → answers. The tool_call_id must match so the LLM can correlate which result belongs to which call (important when 3+ tools are called in parallel).
